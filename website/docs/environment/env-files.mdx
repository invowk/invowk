## Path Resolution

Paths are relative to the invowkfile location:

<Snippet id="environment/env-files-path-resolution" />

For modules, paths are relative to the module root, and every env file must resolve inside the module directory. Links on the path are followed, but a link that leads outside the module (including one under `invowk_modules/`), a link with an absolute target, or a link that does not resolve fails the command with `env file resolves outside module`. For a module, an optional `?` file is skipped only when nothing exists at its path; a broken or escaping link still fails.

Env files of a plain `invowkfile.cue` (not in a module) are not restricted this way: a `.env` that is a link to a file elsewhere, such as `~/secrets/.env`, keeps working.

## Literal File Paths

`env.files` entries are treated as literal paths (apart from the optional trailing `?` suffix) and do not expand `${VAR}` environment variables. To select per-environment files dynamically at runtime, pass `--ivk-env-file` on the command line or define separate commands/implementations.

## Best Practices

1. **Use `.env` for defaults**: Base configuration that works for everyone
2. **Use `.env.local` for overrides**: Developer-specific settings, not in git
3. **Use separate files per environment**: Load `.env.production` or `.env.staging` via `--ivk-env-file` or dedicated commands
4. **Mark sensitive files optional**: They may not exist in all environments
5. **Don't commit secrets**: Add `.env.secrets`, `.env.local` to `.gitignore`
