# CLI Reference

Complete reference for all Invowk™ command-line commands and flags.

## Global Flags

These flags are available for all commands:

| Flag | Short | Description |
|------|-------|-------------|
| `--help` | `-h` | Show help for the command |
| `--ivk-color` | | Control color output for Invowk's own CLI output: `auto` (default), `always`, `never`. Precedence: `--ivk-color` > `NO_COLOR` / `CLICOLOR_FORCE` / `TERM=dumb` > TTY detection. Invalid values exit `2` |
| `--ivk-config` | `-c` | Config file path. Overrides `INVOWK_CONFIG` and the [user config file](/docs/configuration/overview#configuration-file-location); a missing or invalid file is an error (exit 1; `invowk audit` uses its scan-error code, 2). See [which config file is used](../configuration/overview#which-config-file-is-used) |
| `--ivk-no-cwd` | | Ignore the current directory's `invowkfile.cue` and `*.invowkmod` modules during command discovery (overrides `INVOWK_NO_CWD`) |
| `--ivk-interactive` | `-i` | Run commands in alternate screen buffer (interactive mode) |
| `--ivk-verbose` | `-v` | Enable verbose output |
| `--version` | | Show version information (root command only, not inherited by subcommands) |

### Environment Variables

| Variable | Description |
|----------|-------------|
| `INVOWK_CONFIG` | Absolute path of the config file to use when `--ivk-config` is not given. Empty means unset; a relative, missing or invalid value is an error (exit 1; `invowk audit` uses its scan-error code, 2). Never resolved against the current directory |
| `INVOWK_NO_CWD` | Same as `--ivk-no-cwd` when the flag is not given. Accepts the values of Go's `strconv.ParseBool` (`1`, `true`, `0`, `false`, ...); empty means off, anything else is an error (exit 2) in the commands that discover command sources |
| `NO_COLOR` | When non-empty, omits ANSI escape sequences from Invowk's own CLI output and renders Glamour issue cards with `"notty"` unless `--ivk-color=always` is passed |
| `CLICOLOR_FORCE` | When non-empty and not `"0"`, enables ANSI styling in non-TTY pipes for Invowk's own CLI output unless `NO_COLOR` is set or `--ivk-color=never` is passed |
| `TERM` | `TERM=dumb` disables ANSI styling for Invowk's own CLI output unless `CLICOLOR_FORCE` or `--ivk-color=always` is set |

Nested `invowk` calls inherit `INVOWK_CONFIG` and `INVOWK_NO_CWD` only when the caller set them, under the command's normal `env_inherit_mode` rules; the flag forms are never exported to child processes. User commands always receive raw, unwrapped `stdout`/`stderr` file descriptors, and `invowk tui style` / `invowk tui format` remain opt-in to ANSI styling in pipelines unless `--ivk-color=never` is passed. Color enablement is orthogonal to `ui.color_scheme` (`"auto"`, `"dark"`, `"light"`), which selects the theme when color is enabled.

### invowk cmd

Execute commands defined in invowkfiles.

<Snippet id="reference/cli/cmd-syntax" />

Without a command name, `invowk cmd` lists the available commands: the root invowkfile first, then modules alphabetically, and within each source, commands alphabetically by full name (grouped by category, uncategorized first). Commands configured with `passthrough: true` are annotated with `[passthrough]`.

**Flags:**

| Flag | Short | Description |
|------|-------|-------------|
| `--ivk-runtime` | `-r` | Override the runtime (must be allowed by the command) |
| `--ivk-from` | `-f` | Source to run command from (e.g., 'invowkfile' or module name) |
| `--ivk-force-rebuild` | | Force rebuild of container images (container runtime only) |
| `--ivk-container-name` | | Override the persistent container target name (container runtime only) |
| `--ivk-dry-run` | | Print resolved execution plan without executing |
| `--ivk-watch` | `-W` | Watch mode: re-execute on file changes |
| `--ivk-env-file` | `-e` | Load environment variables from file (repeatable) |
| `--ivk-env-var` | `-E` | Set environment variable (KEY=VALUE, repeatable); a value without `KEY=` is an error (exit `2`), while `KEY=` sets an empty value |
| `--ivk-env-inherit-mode` | | Inherit host environment variables: `none`, `allow`, `all` |
| `--ivk-env-inherit-allow` | | Allowlist host env vars to inherit; requires `--ivk-env-inherit-mode=allow` (repeatable) |
| `--ivk-env-inherit-deny` | | Denylist host env vars to inherit (repeatable) |
| `--ivk-workdir` | `-w` | Override working directory for this command |

:::note Pre-command `--ivk-*` boundary for passthrough commands
All `invowk cmd` persistent `--ivk-*` flags are accepted **before** the command path as well as after normal commands. For commands with `passthrough: true`, only `--ivk-*` flags placed **before** the command path configure Invowk; every token after the command path (including `--help`, `-h`, unknown flags, `--`, and nested `--ivk-*` flags) is forwarded verbatim to the script across direct, `@source`, `--ivk-from`, and `<source> <cmd>` invocations. Because `invowk cmd <name> --help` executes the passthrough command, use `invowk help cmd <name>` to inspect Invowk's command help without executing.
:::

:::note
The `ivk-`, `invowk-`, and `i-` prefixes are reserved for system flags and cannot be used for user-defined flags.
:::

:::note
When `--ivk-watch` runs attached to a terminal with `OSC7577_TOKEN` set, Invowk emits signed OSC 7577 Program Resume reports (`clear=1` on `Ctrl+C` or post-setup errors, preserved on Unix `SIGHUP`/`SIGTERM`, skipped when `--ivk-env-var` is passed or limits are exceeded) and strips `OSC7577_TOKEN` from watched child commands. On attached terminals, `--ivk-watch` and `-i` / `invowk tui *` also emit `OSC 7501` Program Status (`app="invowk"`, cleared on exit) while keeping non-interactive `invowk cmd` silent.
:::

**Command Discovery:**

Commands are discovered from (in priority order):
1. Current directory invowkfile.cue (highest priority)
2. Sibling `*.invowkmod` module directories
3. Configured `includes` entries (modules only)
4. `~/.invowk/cmds/` (modules only, non-recursive)

**Command Disambiguation:**

When a command name exists in multiple sources (e.g., both `invowkfile.cue` and a module), you must disambiguate:

Using `@source` prefix:
```bash
invowk cmd @invowkfile deploy      # Run deploy from invowkfile
invowk cmd @tools deploy         # Run deploy from tools.invowkmod
invowk cmd @tools.invowkmod deploy # Full module name also works
```

Using `--ivk-from` flag:
```bash
invowk cmd --ivk-from invowkfile deploy
invowk cmd --ivk-from tools deploy
```

If you run an ambiguous command without disambiguation, invowk shows an error listing available sources.

:::tip
You can use `@source` or `--ivk-from` even for unique command names to be explicit about where a command comes from.
:::

### invowk validate

Validate invowkfiles, modules, or the entire workspace.

<Snippet id="reference/cli/validate-syntax" />

Without arguments, validates the current workspace by running full discovery
and reporting all diagnostics from every search path.

With a path argument, auto-detects the target type:

| Path | Validation |
|------|-----------|
| `*.invowkmod` directory | Module validation (structure, plus invowkfile parsing and command tree when `invowkfile.cue` is present) |
| `invowkfile.cue` file | Invowkfile validation (CUE schema + structural + command tree) |
| Directory with `invowkfile.cue` | Invowkfile validation |
| `invowkmod.cue` file | Module validation (parent directory) |

:::tip
`invowk validate` performs deep validation on module structure and metadata. When the
module contains `invowkfile.cue`, it also parses that file and validates its command tree;
library-only modules do not run those file-specific checks.
:::

## Exit Codes

Invowk uses these exit-code classes:

| Code | Meaning |
|------|---------|
| `0` | The invocation succeeded. A bare command group (for example `invowk module` or `invowk cmd test`) prints its help and exits `0`. |
| `N` | A user-defined command ran and exited with its own non-zero status `N`, forwarded unchanged for every runtime. |
| `128 + signal` | On Unix, Invowk terminated because it received a trapped termination signal (`129` `SIGHUP`, `130` `SIGINT`, `143` `SIGTERM`) after bounded resource cleanup, except where a built-in defines another code (such as `invowk tui spin`). |
| `2` | Invowk rejected the command line before running any user command code. |
| `1` | Invowk itself failed for any other reason. |

Exit status `2` covers:

- an unknown flag, a flag value that does not parse, a flag without its required value, or a missing required flag, at any level;
- an unknown command, including a typo under a command group and an unknown root command followed by `--help`, `-h` or `--version` (`invowk cmd test nonexistent`, `invowk config bogus`); the group's subcommands are listed on stderr and nothing is written to stdout;
- an argument-count error on a built-in command (`invowk init a b c`);
- a command name under `invowk cmd` that is not found or is ambiguous across sources, an unknown `@source` or `--ivk-from` source, a malformed source name such as a path (`@./m.invowkmod`; name the module `m` instead), and a source filter without a command name;
- declared arguments or flags that fail validation;
- an invalid reserved `--ivk-*` flag value, such as an invalid `--ivk-color` mode (`auto`, `always`, `never`), an unknown `--ivk-runtime` or a runtime the command does not allow, an unknown `--ivk-env-inherit-mode`, an invalid `--ivk-env-inherit-allow`/`--ivk-env-inherit-deny` name, a whitespace-only `--ivk-workdir`, an empty `--ivk-env-file`, an invalid `--ivk-container-name`, or an `--ivk-env-var` value without `KEY=`;
- an `invowk agent` error detected from the command line alone, such as an invalid name, mutually exclusive flags, a missing description, an invalid `--llm-*` value, or an unknown prompt format or operation;
- a conflict decided by flags and environment variables alone: an invalid `INVOWK_NO_CWD` value, `--ivk-watch` together with `--ivk-dry-run`, `invowk config set` while `--ivk-config` or `INVOWK_CONFIG` is active, and `invowk agent cmd create`/`change --verify` under `--ivk-no-cwd` or `INVOWK_NO_CWD`.

Exit status `1` covers everything else: config errors that abort the command, including a config file named by `--ivk-config` or `INVOWK_CONFIG` that is missing or invalid, or a relative `INVOWK_CONFIG`; discovery errors; current-directory source failures (unless `--ivk-no-cwd` or `INVOWK_NO_CWD` is active), where a `./invowkfile.cue` or `./*.invowkmod` fails parse, schema, or `invowk_version` validation and aborts `invowk cmd` immediately with its underlying error rather than falling back to lower-precedence sources; invalid invowkfiles or command trees, including a command that is not found while a non-current-directory invowkfile or module was skipped because it failed to parse or load (the command may be defined there; the error names each skipped source and its diagnostic code, and a miss inside an `@source` or `--ivk-from` source that loaded still exits `2`); unsatisfied `depends_on` checks; an unsupported host platform; an unavailable container engine or runtime; command timeouts (`timeout`) and non-signal cancellations; and `invowk agent` failures that need files, the config or an LLM.

On Unix, trapped termination signals (`SIGHUP` = 1, `SIGINT` = 2, `SIGTERM` = 15) cancel the active execution context, clean up temporary scripts, terminate non-TTY native child process groups, and stop/remove ephemeral containers within a bounded cleanup window before exiting with `128 + signal` (`129`, `130`, `143`). Direct controlling-TTY native runs stay in the terminal's foreground process group so interactive prompts do not block on `SIGTTIN`/`SIGTTOU`. On Windows, `Ctrl+C` (`os.Interrupt`) cancels the execution context, cleans up resources, and exits with status `1`.

Per-command exceptions:

| Command | Codes |
|---------|-------|
| `invowk audit` | `0` clean, `1` findings detected, `2` scan or configuration error; command-line rejections also exit `2` |
| `invowk tui confirm` | `1` when the user declines |
| `invowk tui spin` | the wrapped command's exit code; `1` when cancelled with Ctrl+C, when a signal ended the command, or when it was still running 15 seconds after it was stopped |
| `invowk validate` | `1` when validation finds errors |

:::note
When forwarding a command or built-in exit status (`invowk cmd`, `invowk audit`, `invowk validate`, `invowk tui confirm`, `invowk tui spin`) without an Invowk error message, Invowk forwards the exit status quietly on both TTY and non-TTY streams without printing an `Exit status N` banner. Pass `--ivk-verbose` to emit a single diagnostic status line on stderr.

A user command can exit with `1` or `2` itself, and a nested `invowk` call inside a script can propagate its own usage error. A wrapper that must tell these cases apart reads stderr. The contract is only exact for commands whose scripts avoid codes `1` and `2`.

Container-engine and OCI-runtime failures (exit codes `125` and `126`) are retried as transient. After the retries run out, the code is forwarded as if it were the command's own.
:::

## Error Messages

Invowk provides specific error messages to help diagnose issues:

### No Invowkfile Found

When no invowkfile is discovered in any search location:

<Snippet id="reference/cli/error-no-invowkfile" />

**This message appears when:**
- No `invowkfile.cue` exists in the current directory
- No modules exist in configured `includes`
- No modules exist in `~/.invowk/cmds/`

**Solutions:**
- Run `invowk init` to create an invowkfile in the current directory
- Navigate to a directory containing an invowkfile
- Add module paths to your config's `includes`

### Failed to Parse Invowkfile

When an invowkfile is found but contains syntax errors or invalid configuration:

<Snippet id="reference/cli/error-parse-failed" />

**This message appears when:**
- CUE syntax errors (missing braces, quotes, etc.)
- Invalid field names or values
- Schema validation failures (e.g., invalid runtime type)
- Missing required fields

**Solutions:**
- Check the specific error message shown above the help text
- Validate your CUE syntax: `cue vet invowkfile.cue`
- Run with verbose mode: `invowk --ivk-verbose cmd`
- Compare against the [invowkfile schema reference](./invowkfile-schema)

:::tip
The error message always shows the specific parsing error first (e.g., which field failed validation), followed by general troubleshooting guidance.
:::
