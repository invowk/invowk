# Platform testing skills history

Historical notes moved out of the `windows-testing`, `macos-testing`, `linux-testing` and `fixer` skills on 2026-11-14. None of this is normative; the current skills win on any disagreement.

- **lipgloss `TestMain` pre-warm (fixer RC-1, windows-testing).** Windows TUI tests once hit race-detector reports on lipgloss internal state during parallel tests on `windows-latest`. The diagnosis then was that lipgloss lazily detects terminal capabilities on first render behind a `sync.Once`, and that some versions read the cached result outside the `Once`. The fix tried was a package `TestMain` that rendered once before the tests ran ("pre-warming"). In this repository that pre-warm turned out to be a no-op for the later failure mode, which looked like memory and scheduling pressure under `-race` rather than a data race. The skills now say: do not add `TestMain` pre-warming; treat Windows TUI `-race` failures as pressure unless a fresh `DATA RACE` report with two access stacks proves a race.
- **SSH host key collision (fixer RC-3, resolved).** Parallel SSH server tests used to fail with `permission denied` / `file exists` on `id_ed25519`, or trip the race detector, because the `wish` library's default wrote host keys relative to the process working directory. `sshserver.Server` now always sets a host key through `hostKeyOption()` (`internal/sshserver/server_lifecycle.go`): an in-memory ephemeral key when `Config.HostKeyPath` is nil, otherwise a stable key at the configured path. A repo-wide `.gitignore` `id_ed25519*` pattern is the backstop. If the symptom returns, a new server construction path bypasses `hostKeyOption()`.
- **Engine masking with `|| true`.** The CI engine-masking steps once ran `sudo mv /usr/bin/docker /usr/bin/docker.disabled || true` (and the Podman equivalent), so a missing or relocated binary was skipped silently and a job could test the wrong engine. The steps now loop over `command -v`, rename every `PATH` install, and fail the job if the engine is still on `PATH`.
- **Pre-split platform skill layout.** Before commit `ba22a585` ("harden repository skills"), `macos-testing` and `linux-testing` kept their deep material in `SKILL.md`: timer coalescing, file-descriptor limits, code signing/Gatekeeper/SIP and flock on macOS; process lifecycle, signal table, OOM killer and file locking on Linux. That split dropped those sections without moving them, leaving routers and fixer cross-references dangling. They were restored into the skills' `references/` on 2026-11-14, minus claims the current skills contradict (Go auto-reaping children, cleanup running before a binary timeout, per-process flock on macOS, copied runner capacities and timing constants).
