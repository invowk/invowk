# Git and Commits

- **CRITICAL: sign every commit** (`git commit -S`, with the SSH or GPG signing already configured). The `main` ruleset rejects unsigned commits and requires linear history. To sign by default: `git config --global commit.gpgsign true`.
- **Merge into `main` only by squash merge, through a pull request.** The Safety ruleset on `main` has a pull-request rule (0 approvals, every review option off), so nothing reaches `main` without a PR, and a local `git merge --squash` plus push is rejected. It also blocks deleting and force-pushing `main` (`deletion`, `non_fast_forward`) and requires signatures, linear history and three checks (`goplint consumer gates`; `Models, golden vectors, and correspondence`; `script tests (worktree-safety gate)`); only the `invowk-docs-bot` App (`version-docs.yml`) bypasses it. Squash is project policy, not a GitHub setting: the repository still enables merge-commit and rebase merging, so choose squash explicitly (`gh pr merge <n> --squash --match-head-commit <sha>`). Recipe and branch cleanup: `.agents/runbooks/git-merge.md`.
- **Release tags are protected.** The "Release tags" ruleset covers `refs/tags/v*` (creation, update, deletion), bypassed only by the repository admin role. `make release` from the maintainer's machine works. Workflow tokens (`GITHUB_TOKEN`) and GitHub App tokens cannot create, move or delete a release tag, since neither holds a repository role; an account token of an admin (a PAT) carries the admin bypass, so treat any admin PAT given to automation as able to cut releases.
- Do not change branch rulesets, required status checks or the CodeQL setup without the maintainer.
- Subject: `type(scope): summary`, at most 72 characters. Body: 3-6 bullets on what changed (and why, when it helps). Call out user-facing behavior, schema changes and migrations. No vague messages such as "misc" or "wip".
- In scripted bodies use real newlines (`git commit -F -`, a message file, or repeated `-m`); never write escaped `\n`.
- Keep existing trailers, in canonical `Key: Value` form, at the end of the message.

Example: `refactor(invowkfile): rename commands to cmds`, with bullets such as "- Rename root field `commands` -> `cmds`".
