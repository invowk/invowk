## 3. Terminal emulation (commit 2)

- [ ] 3.1 Replace `content strings.Builder` and the live viewport in `interactiveModel` with a `*vt.Emulator` sized to the command area (design D3): `outputMsg` carries bytes and is written in `Update`; `View` renders header, `Render()`, footer, the overlay on top and the child's visible cursor; resize keeps emulator and pty equal; remove `stripOSCSequences` and its test; write server styled text into the emulator with `\n` -> `\r\n`; carry out task 2.1 once vt is imported. Model tests build the emulator through the task 3.2 constructor, so its replies always have a reader. Verify with model unit tests: a cursor-up repaint leaves one frame, `\r` progress leaves `done`, an OSC split across two `outputMsg`s draws nothing, styled text appears on the screen.
- [ ] 3.2 Reply pump and pty writer (design D5): one constructor creates the emulator, the pump (reads `Emulator.Read`, hands chunks to a bounded queue of at most 64 KiB without blocking, drops and counts what does not fit) and the writer (writes queued chunks to the terminal); the session closes the input pipe writer at session end, never `Emulator.Close`. Verify with `go test -race` tests: a DA1 query gets `ESC [ ?…c`; a CPR query from 1;1 gets `ESC [ 1 ; 1 R`; with a terminal fake whose `Write` blocks forever, 10,000 DA1 queries and 1,000 keys sent through `Update` return within 2 s, the drop count is non-zero, and a following Ctrl+\ `KeyPressMsg` still returns the force-quit command; the pump ends with the session; the writer ends once the fake is closed.
- [ ] 3.3 Key encoding (design D6): convert `tea.KeyPressMsg` to vt's `KeyPressEvent`; clear `IsRepeat`, `BaseCode`, `ShiftedCode`; mask Caps Lock, Num Lock and Scroll Lock; send Ctrl+Shift+letter as Ctrl+letter; clear `Text` under Ctrl; send a text-less key with Shift, Ctrl or Meta outside vt's modified bindings as the plain key (Alt kept); drop special keys vt does not encode and Ctrl+text keys with no control character; send through `Emulator.SendKey`; forward `tea.PasteMsg` through `Emulator.Paste`; keep Ctrl+\ as force quit, intercepted before `SendKey` with lock modifiers ignored; remove `forwardKeyToPty`. Verify with a table test over Ctrl+A..Z, Ctrl+Shift+A, Alt+x, Enter, Tab, Shift+Tab, Backspace, Esc, arrows in normal and application-cursor mode, Home/End/PgUp/PgDn/Delete, F1, shifted and non-ASCII text, a repeated key, lock-modified rows (Caps Lock + Ctrl+A -> `001`, Num Lock + Enter -> `\r`, Caps Lock + Up -> `ESC [ A`, Caps Lock + Ctrl+\ -> force quit), modified special keys (Ctrl+Left -> `ESC [ D`, Shift+Up -> `ESC [ A`, Shift+Enter -> `\r`, Alt+Ctrl+Left -> `ESC ESC [ D`), and bracketed and plain paste.

- [ ] 3.5 Completion ordering (design D8): close the parent's slave copy after `Start` on Unix (ignore `os.ErrClosed` on the later `Close`), sequence reader end and waiter with the bounded grace period, and after `doneMsg` keep writing `outputMsg`s to the emulator and rebuild the completed view (banner last, at most once per frame, scroll offset kept or bottom followed).
