# Design

## Context

Eight independent items share one change (proposal.md, Why). Each decision below names the current behaviour it changes, with file:line on the base `origin/main` 88f44a6e.

- **Drawn table (D1).** `newTableModelWithStyles` builds the bubbles table with columns, rows, focus and height but no width (`internal/tui/table.go:375-380`); only `SetSize` sets one (`table.go:138-147`), and only the TUI-server overlay calls it (`internal/tui/embeddable.go:303-305`). The bubbles table's `View` is the header plus its viewport (`charm.land/bubbles/v2@v2.2.1/table/table.go:251-253`), and the viewport renders nothing when its width is 0 (`viewport/viewport.go:737-739`). So a directly drawn table, the path of `invowk tui table` without a TUI server (`cmd/invowk/tui_table.go:259-277` -> `table.go:151-176`), shows the header and its rule and blank lines. Reproduced in this stage with the base binary in tmux 120x30, both with and without `--selectable`. The existing tmux tests wait only for the header text `name` (`tests/cli/tui_tmux_test.go:397-401`, `:425-427`), so they pass on the bug.
- **Table cell text (D2).** `tableTextCells` maps `unicode.IsControl` runes to a space (`internal/tui/table_text.go:72-82`). `strings.Map` already writes every invalid UTF-8 byte as U+FFFD, which no doc says (`table_text.go:16-28`; `website/docs/tui/table-and-spin.mdx:45`). The spec scenario for a quoted CSV newline exists (`openspec/specs/tui-component-terminal-io/spec.md:164-166`), but only a unit test covers it (`internal/tui/tui_table_text_test.go:67-68`); no testscript does. The constant `errTUISpinNotRunMsg` is at `cmd/invowk/tui_spin.go:33-34`, used at `:39`.
- **Double Start (D3).** `TransitionToStarting` checks the caller's context before the state (`internal/core/serverbase/base.go:96-100`) and then calls `TransitionToFailed`, which moves any non-terminal state to Failed and cancels the server context (`base.go:134-155`, via `casToTerminalLocked`, `:271-281`). So a second `Start` with a cancelled context marks a Starting or Running server Failed, and on a terminal server with no recorded failure it returns the recorded `nil` (`base.go:136-140`). #213 documented this as outside the contract: the `Stop` godoc (`internal/sshserver/server_lifecycle.go:174-179`), the `Start` comment and terminal check (`server_lifecycle.go:101-106`), the main spec (`openspec/specs/host-callback-server-lifecycle/spec.md:52`) and the server skill (`.agents/skills/server/SKILL.md:72-77`). `tuiserver.Start` has the same shape (`internal/tuiserver/server.go:138-153`). The Serverbase model's Start step takes the cancelled branch in any state (`formal/tla/Serverbase.tla:94-97`), and the Go sequential model mirrors it (`internal/core/serverbase/base_formal_test.go:59-63`).
- **F11 (D4).** `teardown` closes the listener, waits for the serve gate and then calls the library's graceful `Shutdown` (`internal/sshserver/server_lifecycle.go:296-318`). `Shutdown` closes the listeners and waits on `listenerWg` and `connWg` until its context ends, closing no connection (`charm.land/ssh@v0.4.3/server.go:268-287`); so `Stop` returns `context.DeadlineExceeded` while a client is connected, which the replay `TestHostCallbackToken_StopLeavesAuthenticatedConnectionOpen` asserts (`internal/sshserver/token_formal_test.go:126-169`) and the model's base configuration mirrors (`StopClosesSessions = "FALSE"`, `formal/manifest.toml:976`; `findingF11StopKeepsSessions`, `:998-1003`). The library adds a connection to `connWg` after its handshake, in the connection goroutine (`server.go:448-449`, `:605-617`), so a handshake that completes while `Shutdown` waits is an `Add` concurrent with `Wait` (gliderlabs/ssh#117, decision 120). Every accepted connection already passes through invowk's `ConnCallback` wrapper before its handshake (`internal/sshserver/server_conns.go:55-64`); only authenticated ones are indexed by token (`server_conns.go:70-88`).
- **Watcher flake (D5).** On windows-latest, run 45517294042 (job "Test (windows)", step "Run tests (short)", PR #208, 2026-11-25T00:28Z) failed `TestWatcherDebounce` at `internal/watch/watcher_test.go:262`: "spurious callback fired after initial debounced callback", 0.33 s. The test writes three files 20 ms apart with a 100 ms debounce and then asserts that no second callback fires within 300 ms (`watcher_test.go:239-268`) and that exactly one fired (`:278-280`). The debounce is trailing: every matching event re-arms the timer, and an event after the callback starts a new window (`internal/watch/watcher.go:431-468`). An event that the OS reports after the window closed therefore correctly gives a second callback.
- **acp-go-sdk (D6).** `go.mod` pins `github.com/coder/acp-go-sdk v0.13.5`; Dependabot PR #190 (now closed) bumped it with nine others and broke `internal/acpclient`. Building `./internal/acpclient` against v0.20.0 with a scratch modfile gives 17 errors: `callbackClient` lacks `CompleteElicitation` and `CreateElicitation`; `ReadTextFileRequest.Line`/`Limit`, `CreateTerminalRequest.OutputByteLimit` and `WaitForTerminalExitResponse.ExitCode` are `*int64`; `TerminalId` is a named type; and the `ToolCallUpdate` fields `Title`, `Kind`, `Status`, `Content` and `Locations` are `acp.Patch[T]` (`internal/acpclient/client.go:20`, `:67`, `:276-280`, `:335`, `:393`, `:446-450`, `:499-511`, `:587`). v0.20.0 (2026-11-18) adds no module to the build list (`go.mod` of the SDK has no requirements), is Apache-2.0 and ships `MIGRATION_v0.20.md`. Context7 (`/coder/acp-go-sdk`) says a client that does not offer a capability returns `acp.NewMethodNotFound` and leaves the capability out of `ClientCapabilities`; invowk advertises only fs and, optionally, terminal (`client.go:71-77`). `internal/acpclient` has no production importer (only `import_boundary_test.go`; decision 124).
- **Provision binary (D7).** `Provision` resolves the binary with `checkLinuxBinary`, which opens the path (`internal/provision/binary_resolution.go:145-169`, `binary_format.go:157-162`); `calculateCacheKey` opens it again for `CalculateFileHash` (`layer_provisioner.go:222-228`, `helpers.go:21-34`); and on a cache miss `prepareBuildContext` opens it a third time in `CopyFile` (`layer_provisioner.go:339-347`, `helpers.go:177-200`). `GetProvisionedImageTag` runs the first two steps (`layer_provisioner.go:171-177`). `CopyFile` returns `nil` without copying when its source is not a regular file (`helpers.go:182-185`), so a `binary_path` that is a symlink passes the check and the hash, is not copied, and fails the build at `COPY invowk` (`internal/provision/dockerfile.go:31`).
- **Unix `-i` hang-up (D8).** creack/pty opens `/dev/ptmx` with `os.OpenFile` (`github.com/creack/pty@v1.1.24/pty_linux.go:14`) and runs its ioctls through `f.Fd()` (`ioctl.go:8-10`), which puts the master in blocking mode. The viewer's writer goroutine writes replies and keys to the master (`internal/tui/interactive_screen.go:182`) and its reader reads it (`internal/tui/interactive_session.go:93-104`); the session does not wait for the writer (`interactive_session.go:44-46`). The adapter closes the pty after the session (`internal/app/commandadapters/interactive_session.go:25-31`, `xpty@v0.1.4/pty.go:39-51`). On a blocking `*os.File`, `Close` leaves the descriptor open until an in-flight `Read` or `Write` returns, so a command that reads nothing and writes nothing keeps the master open: SIGHUP reaches it only when invowk exits (decision 132, from #215's run).

## Decisions

### D1. The drawn table gets a width

`newTableModelWithStyles` sets the table's width when it builds it: `opts.Width` when set, otherwise the natural width of the columns (the sum of each column's width plus the horizontal frame of the cell style, which is what one rendered row measures). The standalone model handles `tea.WindowSizeMsg`: when no width was configured, it sets the table width to the smaller of the natural width and the terminal width, so a table wider than the terminal is cut at the terminal edge instead of wrapping (spec "A drawn table shows its data rows"). `SetSize` keeps overriding both for the overlay. The selected-row styles stay. Alternative: call `SetWidth` from `Table()` only. Rejected: `NewTableModel` and `TableBuilder.Model()` would keep building a table that draws no rows.

Tests: a unit test that `View()` of a model from `NewTableModel` with two rows contains both rows' cells (fails on the base: the view holds only the header and blank lines), and a tmux test (`TestTUI_Table`, new subtests for display and `--selectable`) that waits for `Alice` and `Bob` on separate lines before any key, then for the selectable one sends Down and Enter and checks the printed row. The tmux test is written first and seen failing on the base binary (brief: reproduce first).

### D2. Format and separator characters become spaces

`tableTextCells` maps a rune to a space when `unicode.IsControl(r) || unicode.Is(unicode.Cf, r) || r == ' ' || r == ' '` (U+2028 is Zl and U+2029 is Zp; both categories hold only that one character). Invalid UTF-8 keeps becoming U+FFFD through `strings.Map`; the godoc of `WriteTableText`, the spec, and the table docs (en and pt-BR) now say so. Trade-off, accepted by decision 125.4: Cf includes U+200D ZERO WIDTH JOINER and U+00AD SOFT HYPHEN, so a ZWJ emoji sequence is printed as its parts separated by spaces, and a soft hyphen as a space. Alternative: drop the characters instead of a space. Rejected: the brief says "as control characters already are", and a space keeps the replaced position visible.

The rename `errTUISpinNotRunMsg` -> `tuiSpinNotRunErrMsg` touches `cmd/invowk/tui_spin.go` only. The new testscript case goes into `tests/cli/testdata/tui_no_terminal.txtar` (it already runs table without a terminal and needs no mirror): a `rows.csv` with `Alice,"line1` / `line2"` and the expected two lines, plus a stdin case with U+202E and U+200B in a cell.

### D3. The Created check comes first in TransitionToStarting

`TransitionToStarting` takes `stateMu`, reads the state, and returns `cannot start server in state <state>` without any change when it is not Created. Only for a Created server does it look at the caller's context: already cancelled -> record the failure and move to Failed through the same locked steps `TransitionToFailed` uses (a lock-free `TransitionToStopping` can still move Created -> Stopped concurrently, so the terminal move keeps the compare-and-swap of `casToTerminalLocked`, F2), and cancel nothing (no server context exists yet); otherwise the existing CAS to Starting and context store, in the same critical section (F1). The two outcomes for a Created server are unchanged, so every existing test of a first `Start` keeps passing.

What follows from it:
- `sshserver.Start` keeps its `State().IsTerminal()` check after `TransitionToStarting` (`server_lifecycle.go:101-106`) as cheap defence; its comment no longer says the base returns `nil` there. The "server started at most once" sentences go from the `Stop` godoc, the main spec (delta "Stop during Start leaves nothing running") and the server skill; the skill's Start caveat becomes "returns an error in any state but Created".
- `tuiserver.Start` needs no code change; it gets the same double-Start tests.
- The two tests that expect Failed after a first `Start` with a cancelled context (`internal/sshserver/server_test.go:388-405`, `internal/tuiserver/server_test.go:190-208`) stay as they are.

Formal plan (the `formal-verification` skill's procedure). `Serverbase.tla` gets a constant `FixStartGuard`. With it TRUE, the cancelled branch of `StartBegin` takes the lock, and fails only from Created; otherwise it unlocks and ends. A history variable records whether a cancelled `Start` ever changed a state other than Created, and a new property `CancelledStartChangesOnlyCreated` says it never did. New manifest commands: `cancelledStartGuardFixed` (pass) and `mutantPreFixCancelledStartFailsAny` (`FixStartGuard = FALSE`, counterexample, `mutant_of` the former); the base constants set `FixStartGuard = TRUE`, and the `distinct_states` of every Serverbase command are re-measured. `base_formal_test.go`'s `sequentialStep` makes `opStartCancelled` fail only from Created, and the trace harness (`base_trace_test.go`, `ServerbaseTrace.tla`) is checked for the same step. The correspondence row "Starting steps" keeps its binding; its abstraction gains "the state check precedes the context check". This is a decision-120 follow-up, not a model finding: no F-number is assigned, so the change cannot collide with the numbering of the parallel W1a run. The pre-fix code stays only as the mutant configuration.

### D4. Stop closes every connection and uses the library's Close

The brief asks whether closing the connections lets `Stop` avoid waiting on the library's `connWg`. Closing them is not enough by itself: `Shutdown` still waits on `connWg`, and a connection whose handshake finishes after `Stop` closed the known connections calls `connWg.Add` while `Shutdown` waits (`server.go:448-449`, `:605-617`, `:274-279`). But once `Stop` closes every connection, the graceful `Shutdown` has nothing left to be graceful about, and the library's `Close` (`server.go:250-261`: closes the done channel, the listeners and its tracked connections, and waits for nothing) does the rest. No `Wait` on `connWg` runs anywhere, so gliderlabs/ssh#117 no longer applies. The decision is therefore to use it:

1. The `ConnCallback` wrapper registers every accepted connection in a server-owned set, under a mutex, and counts it in a server-owned `sync.WaitGroup`. When a teardown has begun, the callback refuses (returns `nil`, which makes the library close the raw connection, `server.go:401-406`), so every `Add` happens before the teardown's `Wait`, under the same mutex.
2. `tokenConn.Close` removes the connection from the set and from its token's index and calls `Done` once (`closeOnce`, `server_conns.go:45-51`). Revocation keeps closing the token's connections (F7).
3. `teardown`, after the listener close and the gate wait it has today (#213's ordering stays), marks the set closed, closes every connection in it, calls the library's `Close` instead of `Shutdown`, and waits for the connection WaitGroup, bounded by `ShutdownTimeout` (an expiry returns an error wrapping `context.DeadlineExceeded`, as today). The `beforeShutdown` hook runs before `Close`.

The connection goroutine calls `tokenConn.Close` from its deferred `conn.Close` (`server.go:421`), so `Stop` returning still means every connection goroutine has passed the point where the library's `connWg.Done` runs today. The serve gate is kept: with `Close` the listener-WaitGroup race of charmbracelet/ssh#61 cannot occur either, but the gate is what the main spec and #213's tests rely on, and removing it is a separate decision once upstream fixes #61 (decision 120).

Alternative: close the token-indexed connections, then call `Shutdown`. Rejected: it fixes F11 for authenticated connections but keeps #117 and leaves connections in their handshake to the timeout.

Tests: invert the F11 replay as `TestHostCallbackToken_StopClosesAuthenticatedConnection` (Stop returns `nil` well inside `ShutdownTimeout`, the client sees its connection closed, `NewSession` fails); a deterministic Stop-during-handshake test with a new test hook in the password handler (the login is held, `Stop` runs, the hold is released; `-race`); revocation racing `Stop`; #213's lifecycle tests unchanged and green. The inverted replay fails on the base (the base returns `DeadlineExceeded`); the handshake test is the regression test for #117 under `-race` and may pass on the base when the race does not trigger, which the result says.

Formal plan: `HostCallbackToken` base constants set `StopClosesSessions = "TRUE"`; `findingF11StopKeepsSessions` becomes `mutantPreFixF11StopKeepsSessions` (`StopClosesSessions = "FALSE"`, counterexample, `mutant_of = "noSessionAfterStopFixed"`, no `finding` key); calibration text and `distinct_states` updated; the correspondence row "Stop" binds the inverted test and its abstraction drops "(F11)"; the trace harness `TestHostCallbackToken_TraceHarness` checks that `Stop` closes the sessions it tracks; `formal/README.md` row F11 reads "Fixed: Stop closes every tracked connection; the pre-fix code is kept as `HostCallbackToken.mutantPreFixF11StopKeepsSessions`", status `(shipped)`, as F7's row does. The main spec's Purpose, which calls #117 a known residual and the graceful shutdown a feature, is rewritten in the same commit.

### D5. The real-filesystem debounce test asserts what the OS can guarantee

`TestWatcherDebounce` keeps writing three files on the real watcher, and asserts: the first callback arrives within the timeout; every callback holds only `a.txt`, `b.txt` and `c.txt`; and the union of the callbacks received until the watcher has been quiet for two debounce periods holds all three. It no longer asserts one callback. The exact contract (three events inside one window give exactly one callback with all three paths, and no second callback) moves to a new deterministic test on `fakeWatcherBackend`, with the events sent on its channel and a manual schedule like the existing backend tests (`watcher_test.go:46-98`). The debounce itself is unchanged: an event after the window is a real change and must give a callback. Not formal-relevant: `Watcher.Run` keeps its body, so the `Watch` model and its bindings (`formal/tla/Watch.tla:19-22`) are untouched. Evidence of the fix is the Windows CI job by name ("Test (windows)") passing on the PR's head; the fix stage reports it.

### D6. acp-go-sdk v0.20.0, pinned exactly, with explicit no-elicitation

`go get github.com/coder/acp-go-sdk@v0.20.0` under the heavy lock (W2 owns `go.mod`; no other module moves: checked with a scratch modfile). Migration per `MIGRATION_v0.20.md`:
- `CreateElicitation` returns `acp.CreateElicitationResponse{}` with `acp.NewMethodNotFound("elicitation/create")`; `CompleteElicitation` returns the method-not-found error for `elicitation/complete` (notifications have no reply, so the SDK only logs it); `ClientCapabilities` keeps `Elicitation` nil.
- `Patch` fields are read with `Value()`/`Ptr()`; `IsNull()` reads like unset in a `ToolCallUpdate` (ACP v1, per the guide).
- `*int64` fields: `Line` and `Limit` are clamped to the file's line range before conversion; an exit code stays `int64` into the policy boundary (or is range-checked into the policy's own type); `OutputByteLimit` is clamped to a non-negative int.
- The silent-change list of the guide (`RawInput`, `RawOutput`, `Meta`, typed maps, `fmt` of a Patch, `int` assertions) is grepped in `internal/acpclient`; the base uses none of them except `Content` and `Env`, which the compiler checks.

Dep-audit: `make vulncheck`, the licence (Apache-2.0, compatible with MPL-2.0 use), and the changelog from 0.13.5 to 0.20.0 reviewed for behaviour that `internal/acpclient` relies on (cancellation, `session/cancel` on context end, logger). Existing tests in `internal/acpclient` plus a new one for the elicitation answer. PR #190 is already closed; the result says so instead of asking the maintainer to rebase it.

### D7. One copy, checked and hashed

The flow stays: resolve (check) -> cache key (hash) -> on a miss, build. `calculateCacheKey` returns the binary's hash along with the key, and `Provision` passes it to `buildProvisionedImage`. `prepareBuildContext` copies the binary once: it opens the configured path (following a symlink, as the check and the hash already do), requires the opened file to be regular (`File.Stat`), and streams it into `<build context>/invowk` while hashing the bytes it writes. It then runs `checkLinuxBinary` on the copy with the architecture the resolution used, and compares the copy's hash with the key's. A rejection or a different hash fails the build with an error that names the configured path and says the binary changed during provisioning (spec "The installed binary is the one that was checked"). The `Dockerfile` copies `invowk` from the build context as today. The cache-hit path and `GetProvisionedImageTag` do no copy, so their I/O and the cache key are unchanged (#214's key and drift tests stay green).

So the resolution must carry the architecture it checked against: `binaryResolution` gains it. The copy no longer goes through `CopyFile`; a symlinked `binary_path` is therefore installed instead of failing the build at `COPY` (Context). This is the one behaviour change outside the race, and it follows from the copy this change adds.

Alternatives: one descriptor shared by check, hash and copy. Rejected: it defeats a rename but not an in-place write between the steps. Snapshot the binary to a temp file before the check. Rejected: it copies the whole binary on every run, cache hits included.

Tests (each fails on the base): a seam between resolution and build (an unexported hook on `LayerProvisioner`, like `imageArchitecture`) that replaces the file at `binary_path` with a macOS Mach-O stub, a script, and a different Linux ELF; the fake engine records the build context; the run fails with the named error and no build is recorded, where the base builds with the replaced bytes. Plus a test that an unchanged binary builds the same tag as before.

`internal/provision` is formal-bound, but its only bound function is `CopyDir` (`formal/alloy/ModulePathContainment.als:40`), which this change does not touch; the fix stage still runs `formal_mutation.py symbols` on the changed functions.

### D8. A non-blocking duplicate of the master (investigate, then decide)

Proposed mechanism, without changing `xpty`: after `startInteractivePty` (Unix), duplicate the master descriptor inside `UnixPty.Control` (a raw-descriptor callback that, unlike `Fd()`, does not switch the file to blocking mode), set the duplicate non-blocking, and wrap it with `os.NewFile`, which registers a non-blocking descriptor with the runtime poller. A small adapter type satisfies `tui.InteractiveTerminal`: `Read` and `Write` use the duplicate, `Resize` delegates to the `UnixPty`, and `Close` closes the duplicate first (the poller wakes a blocked `Read` or `Write` with `os.ErrClosed`, and the descriptor closes at once) and then the `UnixPty`. O_NONBLOCK belongs to the open file description, so the original master becomes non-blocking too; the original `*os.File` is then used only for ioctls (`Control`) and its final close, never for `Read` or `Write`, which would see `EAGAIN`. Both the writer and the reader are covered: a command that reads nothing and writes nothing pins the master through a blocked `Read` just as through a blocked `Write`.

Decision rule (brief item 8). Task group 8 starts with a probe test (`interactive_session_unix_test.go`): a command that never reads its input, enough input to fill it, session ended, then the command must receive SIGHUP within a bound while the test process runs on. If the probe passes with the mechanism on Linux and, in CI, on macOS (where kqueue must accept the pty master; if `os.NewFile` cannot register it, the file stays blocking and nothing changes), the item ships with that test. If it needs changes inside `xpty` or creack/pty (for example a master that cannot be duplicated or polled), the fix stage reverts the item's code, removes the delta `specs/interactive-mode-terminal/spec.md` and the unticked tasks of group 8 with a note, and records the finding in the result. That outcome changes no other item.

## Risks / Trade-offs

- [The drawn table's natural width can exceed a narrow terminal] -> D1 clamps it to the terminal width on `WindowSizeMsg`; rows are cut, not wrapped.
- [Cf replacement splits ZWJ emoji and soft hyphens in plain-text output] -> accepted by decision 125.4; documented.
- [`Stop` now ends SSH sessions of executions still running] -> that is F11's fix; production calls `Stop` after executions end (`formal/README.md:265`), so normal runs see no difference.
- [Replacing `Shutdown` with `Close` drops the library's own connection wait] -> the server-owned WaitGroup gives the same ordering point (D4), and the handshake test runs under `-race`.
- [The ConnCallback refusal makes the library close a raw connection a client already opened] -> only after `Stop` began, when the listener is already closed; the client sees a reset, as with a closed port.
- [acp-go-sdk 0.20 is one week old] -> no production caller; tests with fake peers; pinned exactly; Dependabot keeps the group update visible.
- [The provision copy now follows a symlinked `binary_path`] -> consistent with the check and hash, which already follow it; the result lists it as a behaviour change.
- [The non-blocking master behaves differently on macOS] -> D8's decision rule; CI's macOS job runs the probe.
- [Formal ledger conflicts with W1a] -> W1a merges first; mechanical rebase and a fresh targeted refresh (D9).
